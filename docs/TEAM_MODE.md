# 团队模式 V1

团队页 `/teams` 使用真实登录身份与 PostgreSQL 数据，不再使用示例团队或浏览器内模拟账单。团队空间仅覆盖漫剧项目和资产；短视频与独立工具仍属于个人空间。

## 成员与权限

用户可免费创建多个团队。所有有效成员可查看和创作团队内全部漫剧项目。所有者管理团队和成员月额度、任命管理员及所有权转让；管理员可邀请成员、移除普通成员、删除项目和取消队友任务；普通成员仅能取消本人任务。所有者必须先转让再退出。

邀请绑定收件邮箱，有效期 7 天，仅保存令牌摘要；重发会撤销旧令牌。接受时必须登录对应邮箱。已配置邮件服务时发送邀请，否则页面提供可复制链接。签发链接使用 CORS 白名单中的前端 Origin，后台调用回退 `PUBLIC_BASE_URL`。

成员退出或被移除后立即失去读写权限，人工编辑占用同时释放。未开始的任务取消并释放预留额度；已提交上游的任务继续取回结果并按受理时的付款账户结算并记入原团队，新生成请求重新核对有效成员关系。

## 创作与协作

团队列表均由服务端搜索、筛选和分页。旧漫剧资源接口通过数据库实际归属授权，不依赖客户端传来的空间标记。`X-Team-Id` 仅用于列表与创建时选择空间。

编辑租约有效期 120 秒，前端每 30 秒续租。资产按资产 ID 占用，正文与分镜按稳定集号共用占用；不同集、不同资产可并行。结构级修改与项目全部资源互斥，画布布局与独立资产内容分别保存。所有者/管理员可接管人工占用，不能接管尚在执行的系统任务。每次重新获取都会增加 fencing 版本，旧标签页提交返回冲突。

正文使用 `PATCH /api/drama/scripts/{project_id}/episodes/{episode_number}` 按集读改写并校验内容版本。团队接口拒绝整包覆盖 `episode_content`。模型调用期间不持有共享剧本 JSON 行锁，写回时锁定最新内容，仅合并对应集及状态。单集自动后续流程仅处理本集，不刷新其他集或已有资产。

个人项目可以整体、单向迁入当前团队，要求本人所有且没有活动任务或编辑占用。项目与子资源 ID 保持不变，历史个人任务和消费继续属于个人；新任务按团队计费。迁入和任务受理通过项目行锁避免竞争。

资产复制由后端创建新资产并清除任务、画布及强关联 ID；本地媒体复制到目标项目的新文件名。受控 OSS 的稳定对象引用保留，当前删除入口不删除媒体对象。服务端不会为复制请求下载任意 URL。源项目删除不会删除副本文件。媒体链接继续公开，不提供私有媒体访问控制。

## 计费与运行

团队无独立余额，新任务直接扣所有者个人钱包，消费归属保留团队、实际操作成员和项目。受理时保存不可由客户端指定的 billing_payer_user_id，转让所有权不改变已受理任务的付款人。个人钱包流水备注包含团队和实际操作者，个人消费页包含由本人付款的团队用量；成员在团队页查看本人消费。

受理时检查所有者个人可用余额（含该所有者的个人任务和全部团队的排队预留），同时检查团队总月上限与成员月上限。执行时预扣冻结，结束按实结算、退还差额。两级额度都按上海时区自然月统计，跨月任务计入受理月份。null 不限额，0 阻止新付费任务，所有者自己的成员额度也生效。降低上限不取消已受理任务；取消未开始任务释放预留；上游实际费用超过估算仍如实结算，后续任务按剩余额度拦截。关闭计费时不扣款、不占额度。

所有者在“消费与额度”设置团队总月上限，在“成员管理”设置每个成员上限；管理员和普通成员只能看本人额度与消费，用户接口不暴露他人余额和上游成本。团队充值入口和独立余额调账已停用（旧 POST 接口返回 410），所有者通过个人账户充值。历史团队钱包及流水保留只读；无付款快照的旧在途任务继续在旧钱包完成冻结/结算，不重复扣个人账户。旧团队订单若收到有效支付回调，幂等入账至原下单人的个人账户，团队归属保留用于审计。

`TASK_TEAM_MAX_CONCURRENCY` 默认 4，与全站及个人并发限制同时生效。后台派生任务继承可信父任务的发起人与团队，且只能写父任务覆盖的资源。

## 接口与迁移

主要入口：`/api/teams`、`/api/team-invitations/{inspect,accept}`，团队内的 `projects`、`assets`、`members`、`invitations`、`activities`、`usage`、`wallet`、`orders` 与 `edit-locks`。完整参数见运行中的 `/docs`。

新增表在 `models_teams.py`、`models_team_billing.py`、`models_team_locks.py`。按现有启动机制先 `init_db()`，再执行 `_apply_schema_patches()`；团队增量 DDL 位于 `app/team_schema.py`，可重复执行，不删除历史列或搬迁个人余额。若设置 `DATABASE_BOOTSTRAP_ENABLED=false`，更新服务前需显式运行这两步。

在仓库根目录使用现有虚拟环境运行 `backend/.venv/Scripts/python.exe backend/scripts/prepare_team_schema.py` 即可执行这两步，不启动生成任务、支付或邮件。该命令使用 `backend/.env` 的连接配置。

测试只使用 `backend/scripts/run_tests.py` 加载隔离的 `.env.test`，不得直接以业务数据库配置运行集成测试。支付、邮件、模型接口在测试中替换为 stub，不产生真实支付或生成费用。

V1 不提供自定义角色、审批、评论、团队解散和余额转出。

## 平台管理端查询

管理端 `/teams` 提供平台管理员专用的团队列表与详情，可按团队名称、ID、所有者昵称或邮箱搜索，并查看团队规模、所有者个人余额、团队月上限、本月及累计实际消费。

团队详情支持当前/已退出成员、角色和月份筛选，查看成员额度、已消费与预留金额；从成员行可进入该成员的团队消费记录。消费明细可按成员、项目/模型关键词、结算状态及上海日期范围筛选，筛选合计覆盖全部结果，待结算金额不计入已结算合计。团队概况取月度结算账，明细取模型调用用量记录，两者分别标明统计口径。

只读接口为 `GET /api/admin/teams`、`GET /api/admin/teams/{id}`、`GET /api/admin/teams/{id}/members`、`GET /api/admin/teams/{id}/usage-events`，全部要求平台 `role=admin`，无需加入团队。普通团队所有者没有此权限。列表均使用服务端分页；查询不创建钱包、不修改成员及账务，也不返回密码、邀请令牌或原始上游响应。

团队详情提供“设置消费上限”，成员行也可分别设置月额度（包含所有者）。接口为 PATCH /api/admin/teams/{id}/budget 与 PATCH /api/admin/teams/{id}/members/{user_id}/budget，正文 monthly_limit_fen 为非负整数分或 null，最大 100,000,000 分。仅平台管理员可用，成员必须有效；操作与入队共用团队行锁并记录审计动态，不改变钱包或既有消费。需要调整付款账户余额时，在用户管理中调整所有者个人账户。

“历史团队钱包流水”通过 GET /api/admin/teams/{id}/wallet-ledger 查看旧变动金额、变动后余额、操作人及备注，支持仅后台调账、关键词搜索和服务端分页。该历史记录与新任务的个人钱包流水分别保留，不合并或搬迁历史资金。

本次增量迁移新增 teams.monthly_limit_fen、task_runs.billing_payer_user_id 和 usage_events.billing_payer_user_id 及索引，均为可空列，不回填历史付款人。回滚需保留新增字段并使带付款快照的任务继续由新版结算，不能直接将这类任务交给旧版团队钱包结算逻辑。
