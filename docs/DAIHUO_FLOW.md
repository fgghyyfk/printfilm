# 商品带货：把「一图出套图」并入映创主流程（方案）

> 状态：**P1 已实现**（静图口播片）· 2026-11-03；P2 数字人带货、P3 服饰模特上身待做
> 动态展示视频（静图之外让画面动起来）见 `docs/DAIHUO_MOTION_PLAN.md`
> 前置：一图出套图 MVP 已完成（见 `docs/ECOM_SET_MVP.md`）；广告法极限词库已接入（见第 6 节）

## 1. 目标

用户在映创创作页选择「商品带货」，一次输入商品信息，最后同时拿到两样东西：

1. **电商套图**：主图、卖点图、详情图，直接用于淘宝、抖音等平台的商品页。
2. **带货短视频**：用套图作为画面，配上口播和字幕的竖屏视频；也可以选数字人口播。

当前入口为 `/ecom` 电商工作台（工具中心已下线，不再单独露出套图卡片）。`/daihuo` 保留套图到视频的完整流程；批量任务可直接用成功图片创建带货视频。

## 2. 用户流程

```
创作页 → 选「商品带货」
  ① 商品信息：商品图 + 品名 + 卖点补充 + 平台 + 风格 + 张数（复用套图表单）
  ② 套图方案：AI 看图规划，可改画面和文案 → 确认生成套图（复用套图方案页、生成页）
  ③ 视频设置：视频形式（静图口播片 / 数字人带货）、画幅（默认 9:16）、音色
  ④ 口播稿：AI 根据商品信息和套图卖点写带货口播，每段对应一张套图，可编辑
  ⑤ 出片：沿用现有分镜编辑页、合成和发布流程
交付：项目页同时展示「套图」和「视频」两个页签，套图可打包下载
```

①② 完成后用户也可以只要套图、不做视频，项目就停在「套图已完成」。

## 3. 两种视频形式

| | 静图口播片（P1） | 数字人带货（P2） |
|---|---|---|
| 底层模式 | `pipeline_mode=image_text` | `pipeline_mode=avatar` |
| 画面 | 每段用一张**套图底图**（无字版），加 Ken Burns 推拉镜头 | 数字人口播为主，每段插入对应的套图作为画中画或背景板 |
| 文字 | 视频自己的叠字和字幕（来自套图文案），不用套图上已经排好的字，避免出现两层字 | 同左 |
| 生图费用 | 0：直接复用套图底图 | 0：同左 |
| 依赖 | 现有 image_text 流水线 | 现有数字人流水线，需要新增「段落插图」合成 |

## 4. 数据与代码改动

**数据（只做新增，`_apply_schema_patches` 里补列）**
- `projects.ecom_set_id`：可为空，指向这个项目的套图。
- `ecom_sets.project_id`：可为空，反向关联；独立套图为空。
- 新增模板 `daihuo_product`（分类 `["带货","商业"]`），因此自动走极限词「替换模式」。模板只在只插缺失的 seed 时写入，不覆盖后台改动。

**后端**
- `services/daihuo/`：新包，负责编排，不往 `pipeline.py`（2000 行的历史大文件）里加逻辑。
  - `create_daihuo_project`：建 Project 与 EcomSet 并互相关联。
  - `write_daihuo_script`：LLM 按套图各张的卖点写分段口播，每段对应一张图，输出走 `sanitize_shot_fields(mode=REPLACE)`。
  - `build_shots_from_set`：用套图各张生成 Shot，`image_url` 取套图**底图**（`base_url`），`overlay_title` 取套图标题，`narration` 取口播段。图已就绪，`kepu_stages` 的就绪判定会自动跳过出图阶段，计费也不会再预扣出图费用。
- `pipeline._script_stage`：项目有 `ecom_set_id` 时改走 `write_daihuo_script` + `build_shots_from_set`，不再走通用的分镜 LLM。
- 数字人（P2）：`kepu_avatar_look.write_script` 增加文案风格 `daihuo`（极限词已按带货替换），合成环节增加「段落插图」。
- 套图接口保留在 `/api/tools/ecom-set`，增加 `project_id` 维度；规划和生成复用现有 service，不重写。

**前端**
- 创作页新增「商品带货」入口，进入新页面 `DaihuoCreatePage`，复用 `components/ecomSet/*` 的表单、方案卡片和生成网格。
- 套图生成完成后进入「视频设置 → 口播稿」，然后跳到现有的分镜编辑页。
- 项目页加「套图」页签。
- 工具中心去掉套图卡片；`/tools/ecom-set` 重定向到创作页的商品带货，个人中心历史里已有的套图仍能打开。

## 5. 计费

| 环节 | 计费 |
|---|---|
| 套图规划 | 不变，¥0.10/次 |
| 套图生图 | 不变，按张收费 |
| 带货口播稿 | 与科普写稿一致（LLM 用量） |
| 静图口播片 | 只收配音和合成；不收出图费（复用套图） |
| 数字人带货 | 与现有数字人一致（按秒） |

`resolve_kepu_billing_phase()` 的就绪判定不需要改：套图底图写入 `image_url` 后，出图阶段视为已就绪。上线前要补一条测试确认这一点。

## 6. 广告法合规（已完成）

- 带货项目（模板分类含「带货/获客」，或允许保留店名的获客模板）：口播、叠字、标题在生成和用户编辑时都会自动替换极限词。
- 科普和漫剧：不改字。编辑页调用 `GET /api/projects/{id}/compliance`、`GET /api/drama/episodes/{id}/compliance` 显示提示条。
- 套图：文案和画面描述都自动替换；生图提示词禁止画面出现文字和其他品牌的 logo。
- 管理后台「系统设置 → 内容合规」可以维护自定义禁用词，也可以试检一段文字。

## 7. 排期

- **P1（约 1 周）**：数据关联、带货模板、口播稿生成、按套图建分镜、静图口播片出片、创作页入口、项目页套图页签、工具中心去掉卡片。
- **P2（约 1 周）**：数字人带货（`daihuo` 文案风格 + 段落插图合成）。
- **P3**：服饰类「模特上身」槽位，等丝巾试验会话的结论出来再定方案。
- **与 P1 同期**：商品外观还原问题（实测中出现商品变形、凭空加上别家 logo），优先评估「抠图 + 合成 + 重新打光」的方案。

## 8. P1 实现记录

- 后端：`services/daihuo/`（`script.py` 写稿解析、`frames.py` 补画幅、`service.py` 编排）、模板 `templates_seed_daihuo.py`、`projects.ecom_set_id` / `ecom_sets.project_id`（`_apply_schema_patches` 补列）。
- 接口：`POST /api/tools/ecom-set/{id}/project`（同一套图重复调用返回同一项目）→ 再调已有的 `POST /api/projects/{id}/generate`。写稿阶段 `pipeline._script_stage` 检测到 `ecom_set_id` 时走带货分支。
- 画面：套图底图按视频画幅补边，背景用同图模糊填充，商品不被裁切；分镜直接标为「图已就绪」，出图阶段自动跳过，也不预扣出图费。
- 实测（保温壶套图 4 张 → 9:16）：写稿 → 配音 → 合成全流程跑通，成片约 21 秒，合规扫描 0 处命中。
- 顺带修复：字幕去标点会删掉数字里的小数点（2.5L 显示成 25L），影响所有科普成片，已在 `ffmpeg_compose._strip_caption_punct` 修复。
- 已知问题：成片质量取决于套图的商品还原度，目前套图存在商品变形问题（见第 7 节）。

## 10. E6 新入口：批量图片到带货分镜（2026-11-05）

- 导航、首页和开始创作弹层统一进入 `/ecom`；工作台按准备素材、出图、出海、视频分组，下方以 `GET /api/tools/ecom/recent?page=1&page_size=12&kind=style` 聚合套图和批量任务，用户隔离、数据库筛选、时间倒序和稳定分页。
- 任意 `ecom_jobs` 成功结果的「送到下一步」菜单可进入套图、风格复刻或 SKU 替换。只传 `source_job_id` / `source_item_idx`，后端重新校验归属与状态；风格复刻把来源用作设计参考，SKU 把来源用作场景原图，产品仍由用户上传。
- 套图沿用 `/daihuo?id=…` 的视频设置；批量任务至少两张成功图时可进入 `/ecom/video?job_id=…`，补充品名和卖点，选择画幅、音色，查看费用并确认写稿。
- 批量结果接口：`GET /api/tools/ecom/jobs/{id}/project` 读最近项目，`POST .../project/quote` 只读报价，`POST .../project` 建草稿。首次创建复用最近项目；明确「再做一条」时带 `create_new=true` 和独立 `request_id`，重复请求幂等且保留旧项目。
- 新表 `ecom_job_videos` 在 `models_ecom.py` 登记，由 `create_all` 创建；记录来源 job、项目、请求键和图片快照，不给既有表增加列。创建时把成功图片复制到项目目录，之后源任务重试不会改变已建视频的素材。
- `services/daihuo/images.py` 提供共用图片列表建草稿与报价；套图适配器与 `job_source.py` 共用 `service.build_daihuo_shots` 写口播、补边和建分镜，继续现有 `image_text` 分阶段流水线和广告文案合规。
- 套图优先使用无字底图；批量结果可能本身带字，直接复用原图。对翻译图等已有文字的结果，成片叠字可能重叠，应在分镜编辑页检查。

本次测试只验证本地 mock 和应用逻辑，不代表真实上游出图、配音、成片质量或线上发布验收。

E6 视频设置面板确认后调用 `POST /api/tools/ecom/projects/{id}/script`，仅启动脚本阶段；已有分镜或活动任务直接进入原项目，配音等后续阶段仍需在分镜页确认。
