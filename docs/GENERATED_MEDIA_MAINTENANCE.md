# 本地媒体维护

OSS启用后，现有任务维护循环每5分钟启动一个后台补传批次，最多20个URL。重复tick复用在途批次；上传使用线程，既有调度、取消、对账继续运行。即时上传和补传共享每URL互斥，失败后保本地并在后续轮转中重试。

扫描保持原范围：科普成片、模板预览、已发布作品、漫剧资产/分镜媒体及原资产params媒体键；不把科普分镜中间图、音轨、视频扩大到自动OSS扫描。稳定游标会继续向后扫描，缺文件或失败记录不阻塞后续媒体。任何补传结果都不删除本地副本，FFmpeg及历史引用继续可用。

手动审阅仍可在backend目录运行 `python -m scripts.backfill_oss_media --dry-run --limit 20`；关闭OSS时自动维护与手动补传均不扫描数据库。

## 本地孤儿审计与显式回收

在backend目录运行 `python -m scripts.audit_generated_media` 默认只读审计，保留期默认30天；只有显式 `--apply` 才删除候选单个文件。显式回收用于暂停媒体写入的维护窗口；数据库引用与文件删除不组成跨系统事务，不设置全站写者协议或自动删除任务。

范围刻意保守：只考虑生成根顶层 `pN`（N>0），科普与漫剧同号项目任一存在即整个目录保留。历史记录中的项目归属同样保护；`p0`、tools、users、电商及其它布局默认不回收。活项目中间文件、full_narration和FFmpeg缓存不按OSS上传结果删除。删除项目保留原数据库业务行为，但不再在数据库提交前递归删除共享目录；媒体交给本审计与保留规则处理。

审计按主键分页读全部已登记表的所有列和嵌套/编码JSON：包括作品、用户头像、模板与全局配置，科普/漫剧全部媒体和历史版本，套图本地路径，以及终态/活跃TaskRun、TaskStep、TaskEvent、TaskTarget的payload/result/metadata。未登记表、列不一致、任何查询或遍历失败都禁止apply。报告只含本地规范路径、拥有者表/记录标识与固定错误码，不输出配置、密钥、原始JSON或签名URL。

只有mtime和ctime均超过保留期且完整审计无引用的普通文件才成为候选；符号链接、`.part`和新文件跳过。每个删除前重做完整引用审计与文件身份核对；新引用、文件变化或审计失败都保留。通过逐级不跟随符号链接的目录句柄删除单个文件，不递归删除目录。上传成功、删除某一域项目、或文件在OSS有副本均不独立构成本地删除依据。

本次仅以注入的测试临时目录验证以上行为，没有扫描或清理用户真实generated目录。
