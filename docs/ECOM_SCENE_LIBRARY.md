# 电商图「场景库」功能方案

> 状态：**P1 已实现**（场景可选 + 日化/标品原图合成）· 2026-11-09；P2 自定义、P3 品牌与运营待做
> 背景：Van Reed 日化样稿的反馈是「产品比例要协调，场景要和产品搭配」。场景是商品图质量的关键，而且不同老板、运营各有偏好，需要做成一个可选、可改、可沉淀的完整功能。

## 1. 现状与问题

| 现状 | 问题 |
|---|---|
| `/ecom` 主流程写死 `style: 'minimal'`（`EcomStudioPage.tsx:73`、`styled.py:99`） | 用户完全选不了场景 |
| 风格只有 5 个泛风格（`presets.py STYLES`：简约/清新/科技/温馨/促销），只给旧版 `/daihuo` 用 | 太粗，不分行业，和商品无关 |
| 服饰/首饰/包袋/丝巾的背景硬写在槽位提示词和材质里（如丝巾街拍固定「石板街道」） | 改场景要改代码 |
| 每张图的 `scene` 由规划模型自由发挥，用户只能逐张改文字 | 一套图场景不统一，用户也不会写提示词 |
| 先生成空场景再贴产品 | AI 不知道产品多大，道具比例失调（已在样稿 v2 中改为「先摆产品再搭景」） |
| 没有任何「我的场景」「品牌固定场景」 | 老板/运营的偏好无法沉淀，每次重来 |

## 2. 目标

1. **按行业快速选**：选了品类就推荐 6～8 个对路的场景卡，带预览图，点一下就用。
2. **能自定义**：在场景卡上微调（背景色、台面、道具、光线、构图），或一句话描述，或上传一张喜欢的参考图「照这个感觉来」。
3. **能沉淀**：好用的场景存为「我的场景」；品牌可以固定一组「品牌场景包」，全店出图风格一致。
4. **场景跟着商品走**：根据商品信息自动配道具（柑橘调配橙子葡萄柚、木质调配老木松针、茶叶配茶具），不需要用户懂摄影。
5. **比例协调、商品不走样**：沿用样稿 v2 的「先摆产品 → AI 搭景 → 原图贴回 + 光色迁移」流程。

## 3. 场景的结构（场景卡）

一个场景 = 下面几个维度的组合。系统预设、我的场景、品牌场景都用同一结构，方便微调和复用。

| 维度 | 说明 | 可选值示例 |
|---|---|---|
| 背景 backdrop | 产品后面是什么 | 纯色无缝 / 柔和渐变 / 微肌理墙面 / 窗光墙（斜光影）/ 室内空间虚化 / 户外自然虚化 |
| 背景色 palette | 主色板（2～3 色） | 暖米驼 / 奶油白 / 莫兰迪绿 / 雾霾蓝 / 黑金 / 酒红 / 高饱和撞色 |
| 台面 surface | 产品立在哪里 | 洞石 / 大理石 / 原木块 / 老木（带树皮）/ 亚麻布 / 水面波纹 / 亚克力台阶 / 镜面 / 沙面 / 无台面（悬浮） |
| 道具 props | 点缀物，可多选，**按产品尺寸等比** | 植物草叶 / 花材 / 水果切片 / 原料（茶叶、咖啡豆、谷物）/ 石头 / 枯枝 / 水花水珠 / 冰块 / 丝绸 / 书本杯具 |
| 光线 light | 光的方向和性质 | 柔和窗光（左/右）/ 树影或百叶窗影 / 逆光通透 / 棚拍柔光无影 / 硬光高反差 |
| 构图 composition | 机位与产品占比 | 平视 / 45° 俯视 / 正俯拍平铺；产品占画面 50%（场景图）～70%（主图）；文案留白在上/下/左/不留 |
| 氛围 mood | 一句话氛围 | 安静高级 / 清晨自然 / 夏日清爽 / 节日喜庆 / 科技冷感 |
| 参考图 ref（可选） | 只借环境、光线、色调，不借商品和人 | 用户上传或从成图保存 |

**生成时拼成提示词**：系统按上表字段拼出场景描述，再叠加商品信息联动的道具（第 6 节）和固定的「保持商品不变」约束。高级用户可以展开「提示词」直接改写。

## 4. 场景从哪里来：三层

| 层级 | 谁维护 | 用途 | 可见范围 |
|---|---|---|---|
| **系统场景**（行业预设） | 平台运营，在管理后台维护 | 开箱即用，按行业分组 | 所有用户 |
| **品牌场景包** | 品牌管理员 | 一个品牌固定 2～6 个场景 + 色板，保证全店一致；可设为该品牌商品的默认场景 | 品牌/团队成员 |
| **我的场景** | 用户自己 | 收藏系统场景、微调后另存、上传参考图生成、把满意的成图「存为场景」 | 仅自己（可分享到品牌包） |

选择顺序：商品绑定了默认场景就直接用；否则看品牌场景包；再否则按品类推荐系统场景。

## 6. 智能道具联动（场景跟着商品走）

场景定好「背景 + 台面 + 光线」的骨架后，道具按商品信息自动补充，用户可以删改：

| 商品信息 | 自动道具 | 例子 |
|---|---|---|
| 香调/口味（前中后调、口味） | 对应原料 | 柑橘调 → 橙子、葡萄柚；木质调 → 老木、松针；茶香 → 茶叶；玫瑰 → 玫瑰花瓣 |
| 核心成分 | 成分原料示意 | 积雪草 → 积雪草叶；燕麦 → 燕麦粒；咖啡因 → 咖啡豆 |
| 季节/节日 | 季节道具 | 冬季 → 松枝、肉桂；夏季 → 冰块、水花 |
| 品类 | 尺寸参照 | 护手霜 15cm → 道具小巧；家电 → 按真实房间尺度 |

规则：成分道具只做氛围示意，不能暗示功效；不出现其他品牌、货币、国旗、医疗器械等敏感元素（复用极限词库与禁画元素清单）。

## 7. 用户怎么用（交互）

在 `/ecom` 主流程里新增一步 **「选场景」**，位置在「选商品」之后、「选图」之前。模特类品类则放在「选模特」之后，场景作为模特图的环境：

1. **推荐区**：按商品品类展示 6～8 张场景卡（封面图 + 名称），第一张是品牌默认或上次用过的；可以切换行业标签查看其他场景。
2. **点选即用**，右侧显示该场景下的「试拍预览」：用当前商品先出 1 张，按张计费，确认满意再出整套。
3. **微调**：展开后用下拉或色块改背景色、台面、道具（勾选/删除）、光线方向、构图留白；改完可「存为我的场景」。
4. **一句话描述**：比如「放在海边礁石上，傍晚逆光」，系统拆成结构化字段，用户可以继续微调。
5. **上传参考图**：视觉模型看图，提炼背景、台面、道具、光线、色调，生成一张场景卡。生成时还会把参考图作为第三张参考图传入，并写明「只借鉴环境、光线、色调」。
6. **整套一致**：一套图共用一个场景族。主图、卖点、细节、使用场景各自用场景族里的变化（同色板、同材质，换机位和道具），避免每张图风格不一。
7. **从成图存场景**：在套图结果里，对满意的那张点「存为场景」，自动带上它的场景字段和参考图。

## 8. 生成流程（技术）

```
商品抠图 ──┐
           ├─① 按品类比例摆位（产品占 50～70%，多产品不重叠）→ 参考图
场景卡 ────┤
           ├─② AI 按场景搭景（i2i：保持产品位置大小，周围按场景生成台面道具光影）
道具联动 ──┘
           ③ 多尺度边缘匹配找到 AI 画的产品位置 → 原抠图精确贴回
           ④ 低频光色迁移（RGB 分通道）：产品带上场景的色温与明暗，文字、logo 不变
           ⑤ 版式排字（现有 layout.py），输出平台尺寸
```

- 适用于**标品**（日化、美妆、食品、3C、酒、茶等有透明抠图的商品）。服饰、首饰、丝巾走现有的模特流程，场景只替换环境描述（`categories.py` 里写死的背景改为读场景卡）。
- 多产品陈列（一字排开）：匹配改为**按从左到右顺序逐支匹配**，样稿里已发现原方法会认错，必须修。
- 出图分辨率默认 1.5K（≤236 万像素），详情页 790 宽足够，单张上游成本约 ¥0.33。

## 9. 数据与接口

**新表 `ecom_scenes`**（`models_ecom.py`，`create_all` 自动建）

| 字段 | 说明 |
|---|---|
| id, scope | `system` / `brand` / `user` |
| owner_user_id, brand_id | 品牌/团队维度，第一期可先用 user_id 代替 |
| name, industries（JSON）, slots（JSON） | 适用行业、适用槽位（主图/卖点/使用场景…） |
| spec（JSON） | 第 3 节的结构化字段 |
| prompt_override | 高级用户手写的提示词（可空） |
| ref_image_url, cover_url | 参考图、封面预览图 |
| sort_order, is_active, usage_count | 排序、上下架、使用次数（用于热门排序） |

**引用**
- `ecom_products` 加 `default_scene_id`（JSON 字段或新列，按 `_apply_schema_patches` 补列）。
- 生成时把场景**快照**进 `EcomSet.plan.scene`，以后场景被修改也不影响历史套图。

**接口**（挂在 `/api/tools/ecom-scenes`）
- `GET /?industry=&scope=`：列表（系统 + 品牌 + 我的），服务端分页
- `POST /`、`PUT /{id}`、`DELETE /{id}`：我的场景增删改
- `POST /from-text`：一句话描述 → 场景字段
- `POST /from-image`：上传参考图 → 场景字段
- `POST /from-item/{set_id}/{idx}`：从成图存场景
- `POST /{id}/preview`：用当前商品试拍 1 张（计费）

## 13. 排版、融合与商品资料（2026-11-09 第二轮）

起因：Van Reed 两套实测图的反馈——字体粗、字号大；产品像 P 上去的；文案不够丰富，希望能按参考详情生成。

- **细节移植**（`composite.harmonize`）：贴回原图后，按 RGB 分通道用 AI 所画商品的中低频（约商品高度 1/60 尺度）明暗与色温去调制原图，侧光、暗部、暖色跟随场景，文字与 logo 仍是原图像素；原图被放大时适度锐化，场景噪点更多时补同强度颗粒；边缘内收 1px 再 1.2px 柔化，衔接 AI 的轮廓光与接地阴影。实测与 AI 原图的左右明暗基本一致（左 226 / 右 178 vs AI 227 / 177，旧版 219 / 189）。
- **定位更稳**：单支定位改为「归一化互相关 + 离预期位置/大小的先验」，修掉白管在纯色墙上被误配的问题（旧算法预期框差 1 像素就可能贴到错位置；新算法在线上 10 张图 ±6 像素扰动下 50 次全部命中）。
- **商品资料库**（`services/ecom_set/knowledge.py`）：`ecom_products` 新增 `ref_images`（参考详情图，`kind=own|competitor`）与 `knowledge`（结构化资料）。`POST /api/tools/ecom-products/{id}/references` 上传；`POST .../knowledge/extract` 视觉模型逐批读图（长图切成约 768×1400 的切片，每批 6 张，最多 36 张），自己的详情提取卖点/成分/款式香调/规格/用法/场景/品牌故事/FAQ/注意事项/讲述顺序，竞品详情只提取讲述顺序与打动角度；结果与已有资料合并，不清空；`PUT .../knowledge` 人工修改。资料里的极限词只提示不改字，出图文案仍按替换模式过滤。

- **前端**：「我的商品」每款下新增「商品资料」面板（上传自己的/竞品详情、AI 整理、按「字段｜字段」逐行编辑）；结果页新增字体风格切换；文案编辑新增英文小标；选图新增「免费·信息屏」标签。

## 17. 商品实际尺寸与「不加文字」（2026-11-10）

- 起因：客户反馈 AI 出图时商品与道具、手的比例忽大忽小；实拍是真实大小的商品放进场景，详情页一般也标注产品大小。另外有客户只要纯画面、不要图上文字。
- **实际尺寸**：`ecom_products.dims`（JSON，厘米，`{"h","w","d"}`，启动补丁新增列）。新建商品和出图确认页都能填高 / 宽 / 厚；确认页填的会记回商品库，下次自动带出。丝巾（按方巾尺寸）和服饰不填。
  - 出图：每张提示词追加「商品真实尺寸 + 最接近的常见物件参照（如和一部手机差不多）」，合成槽位要求道具按真实大小搭配，手持槽位把商品长、宽换算成「整只手长度的几倍、几根手指宽、占手掌宽几成」，按大小定握法（<6cm 两指捏、>30cm 托着），并要求手腕入镜（`hand_note`），模特槽位（包袋、首饰）按身高比例；质地特写不加。规划补充说明里也带尺寸（`dims.py`）。
  - 新增免费信息屏「尺寸标注」（`goods_info_size`，`sizescreen.py`）：商品抠图 + 高、宽标注线 + 厚度与常见物件参照，标题固定「产品尺寸 / 实物测量 仅供参考」；没填尺寸时自动跳过并提示。产品信息表多一行「尺寸」。
- **不加文字**：确认页「图上文字」可选「不加文字（纯画面）」：AI 槽位不再留文字区、画面铺满，成图不排标题与卖点；信息屏、尺寸图照常排字。套图页字体下拉末尾多了「不加文字」，已出的图可随时切换（只重排、不收费）。接口：`POST /plan` 增加 `dim_h / dim_w / dim_d / no_text`，`PUT /{id}/type-style` 接受 `none`。

### 17.1 成图文字可读性把关

- 所有画在照片上的文字（促销醒目、典雅衬线 / 简约黑体、丝巾竖排标题、卖点胶囊）落笔前都经 `readable.ensure`：取该行字正下方最不利的背景（深字看最暗 0.5%，白字看最亮 0.5%），对比度标题 ≥ 4.5、其余 ≥ 4.0。
- 深字 / 白字按与文字所在列背景的对比度选，不用固定亮度阈值；不够时先同侧加深 / 提亮，再整块加雾面（精致版式）或底板（促销醒目），最后才逐行垫局部雾面。
- `tests/test_ecom_readable.py` 用 25 种背景（各级中间调、暖色墙、渐变、半明半暗、亮窗条纹、杂乱纹理）× 全部版式 × 字体风格 × 留白位置逐字形核对，任何一行看不清的笔画超过 4% 即失败；改排版必须保持通过。

## 17.2 2026-11-11 客户反馈调整

- **道具宁少勿满**：每张默认 2 个元素（原料静物 2、手持 / 多款陈列 1、质地 1）；提示词要求「只放这几样、每样一两件、大面积留白」；原料静物镜头改为「原料点缀」。
- **停用 45° 俯拍**：贴回的商品是正面视角，俯拍透视对不上；`shots.RETIRED_SHOTS`，老套图里已有的保留可读。
- **包装哑光质感**：`composite.harmonize` 只跟随大尺度光影（模糊半径 = 商品高 / 30），提亮上限 1.25、起伏保留 80%，并至少补 σ=2 的实拍颗粒；合成 / 手持提示词要求保持哑光、不加塑料反光。根本办法仍是商品图用自然光实拍抠图。
- **英文花体**：典雅衬线风格的英文小标与信息屏英文标题用 Pinyon Script（SIL OFL，`backend/app/assets/fonts/`），保留大小写。
- **成分图** `goods_ingredients_photo`（`ingredientscreen.py`）：AI 一次出 2×2 成分示意四宫格（按一张计费），切成圆图，按资料排「圆图 + 成分名 + 说明」左右交错，底部「以上为成分示意，不作为产品功效承诺」；资料里成分少于 2 个时跳过并提示。
- **痛点图** `goods_pain`：标题直击使用困扰的合成场景图。
- **默认组合**：第二张改为卖点图，白底图放第 5 张；10 张起带成分图，12 / 14 张带痛点图与质地图。
- **调整顺序**：结果页每张卡片 ‹ › 移动（`PUT /api/tools/ecom-set/{id}/order`，`ordering.py`），镜头 / 元素跟着图走；详情长图与 zip 按新顺序；生成中不能调。

## 17.3 实拍图一键抠白底（2026-11-11，浏览器内抠图）

- 「我的商品」上传日化 / 标品的商品图时，不是透明底的会在保存后**自动抠成透明 PNG**，卡片上显示进度；也可以手动点「抠白底」，抠坏了点「用原图」切回。
- **抠图在用户浏览器里算，不占服务器**：ISNet 通用版（rembg 发布的 `isnet-general-use.onnx`，Apache-2.0）去掉多余输出、转半精度后约 91MB，放站点 `/ecom-models/isnet-fp16.onnx`，首次使用下载一次，存进浏览器 Cache Storage（`kaikou-cutout-v1`），之后直接读。推理用 onnxruntime-web 1.31.1，在后台线程（Web Worker）里跑：优先 WebGPU（实测首张含下载约 17 秒、之后约 0.4 秒/张），不支持时退回 WASM 单线程（约 10 秒/张）。同一页面一次只抠一张。
- 流程：前端经同源接口 `GET /api/tools/ecom-products/{id}/colors/{i}/photo` 取原图 → 浏览器抠图 → `PUT …/colors/{i}/cutout` 上传透明 PNG（后端校验确实带透明通道）→ 替换颜色款商品图，原图存 `photo_image_*`；`DELETE …/cutout` 切回原图。已建好的套图不受影响，新建套图才用新图。
- 抠完只保留商品主体：画面上的文字、明显小于商品的道具会去掉；两支大小相近的同款都保留。主体太小或铺满整张时提示换图；设备内存不足导致线程崩溃时提示换用电脑或直接上传透明底 PNG。
- 拍摄建议：商品单独摆、不要手拿（手指会被抠掉形成缺口），正面、光线均匀、背景尽量干净。
- 部署：模型文件不进仓库也不进镜像，放宿主 `/opt/kaikou/models/web/isnet-fp16.onnx`，只读挂载到 web 容器 `/usr/share/nginx/html/ecom-models`；本地开发放 `frontend/public/ecom-models/`（已 gitignore）。
- 教训：最初版本在服务器上跑 BiRefNet，单张峰值 6~9GB 内存，线上实测时把共享服务器拖垮约 10 分钟（2026-11-11 11:02–11:12）。**任何本地模型上线前必须先测峰值内存，且不在共享服务器上跑大模型推理。**
